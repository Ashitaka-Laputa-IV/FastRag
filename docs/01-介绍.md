# 01 · FastRag 介绍

> 代码基线：`dev@2d9604f`，版本 `0.2.0`。
>
> 这是四份学习文档的第一份。读完它，你应该知道 FastRag 解决什么问题、提供哪些能力、边界在哪里、怎样跑起来，以及接下来该读哪一份。

## 1. 一句话定位

FastRag 是一个**可配置、可在本地运行的文档混合检索问答库**：它把 Markdown 文档切成带原文偏移的 chunk，用 BM25 与向量两路召回，再通过 RRF 或 cross-encoder 重排融合，最后让 LLM 基于检索结果回答。默认配置走云端端点，也可以用 `local` profile 接本机 llama.cpp 服务。

它同时提供三种使用方式：

- Python 库：`from fastrag import ask, stream, RagPipeline`
- 命令行：`fastrag search / rrf / ask / prepare ...`
- 交互式问答：`fastrag ask`，逐 token 流式输出

它不是一个 RAG 框架，也不是一个可直接上线的问答服务。它更像一个**结构完整、边界清楚、适合学习和二次开发的小型 RAG 参考实现**。

## 2. 它解决什么问题

单一检索方式都有明显短板：

| 方式 | 擅长 | 不擅长 |
| --- | --- | --- |
| BM25 关键词 | 精确术语、错误码、函数名、专有名词 | 同义改写、自然语言问句、跨语言 |
| 向量检索 | 语义相似、自然语言问法 | 精确术语、罕见词、短查询 |
| 只做一路 | 实现简单 | 召回质量受限于单一路径 |

FastRag 的做法是：

1. 先让 LLM 判断「这个问题需不需要查资料」，需要时同时产出**英文 BM25 关键词查询**和**英文自然语言向量查询**；
2. 两路并行召回；
3. 用 RRF（按名次融合）或 rerank（按语义相关性重排）合并；
4. 只把排名靠前的若干片段放进回答提示词；
5. 回答、来源、检索计划、耗时等一起返回。

这样既保留了关键词检索的精确性，也利用了向量检索的语义泛化能力。

## 3. 能力清单

### 3.1 数据侧

- 从配置的文档站点索引抓取 Markdown 原文（默认是 docs.langchain.com 的 Python 文档）；
- 按 token 做句子级切块，保留 `source/start/end` 原文偏移；
- chunk id 内容寻址：`sha1(source + "\0" + text)[:16]`；
- `chunks.jsonl` 作为唯一真源，向量与 BM25 都是可重建的派生产物；
- 向量按 chunk id 增量复用，只嵌入新增/变化的块；
- `chunks.jsonl`、向量文件、manifest/meta 和单文件下载使用临时文件 + 原子替换；BM25 索引目录由 `bm25s.save` 直接写入，不保证整个目录的原子性；
- manifest/meta 记录来源指纹与参数；BM25 用它们严格校验，向量主要按 chunk id 复用。

### 3.2 检索侧

- BM25：`bm25s`，支持 method、停用词、最低分过滤；
- 向量：任意 OpenAI 兼容的 embeddings 端点，向量 L2 归一化后用内积检索；
- RRF：支持按通道配置权重与 `rrf_k`；
- 重排：任意 Cohere 风格 `/rerank` 端点（默认 Qwen3-Reranker）；
- 重排失败自动降级为 RRF；
- 两路候选数、最终 top_n、进入回答的上下文条数分别可配；后者实际受 `top_n` 截断限制。

### 3.3 编排侧

- LangGraph `StateGraph` 固定四阶段：`plan_search → retrieve_bm25 / retrieve_vector → fuse → answer`；
- 路由是一次结构化输出调用，不是多轮 agent 决策；
- 不需要检索时直接走对话提示词，跳过检索；
- 路由失败时自动退回「用原问题检索两路」；
- 回答为空时触发模型 fallback；
- 资源懒加载：`import fastrag` 与 `RagPipeline.__init__` 不读盘、不联网；`RagPipeline.from_config()` 会读 TOML，但不读 `.env`。

### 3.4 接口侧

- CLI：`download / chunk / embed / index / prepare / search / rerank / rrf / ask`；
- 库：同步 `ask()`、流式 `stream()`、可复用的 `RagPipeline`；
- 配置：单份 TOML，pydantic 严格校验；
- 提示词：包内默认，可用 `$FASTRAG_HOME/prompts/` 覆盖；
- 云端与全本地两套 profile。

## 4. 它不做什么

明确边界比堆功能更重要。当前版本**不包含**：

| 不做的事 | 说明 |
| --- | --- |
| Web 服务 / UI | 只有 CLI 与 Python API，没有 HTTP 服务、前端或鉴权 |
| 多轮对话 | 每次 `ask` 都是独立单轮；交互循环只是连续单轮，不保留历史 |
| 多租户 / 权限 | 单机单用户假设 |
| PDF/HTML/Word 解析 | 只处理 `.md`；下载器直接抓官方 Markdown 源码 |
| 大规模 ANN | 向量检索是 numpy 全量内积，适合几千到几万 chunk |
| 自动评测 | 没有内置评测集、指标或回归门禁 |
| 引用核验 | 回答里可能引用来源，但不会程序化验证每句话是否真出自该来源 |
| 增量 BM25 | 语料变化后 BM25 需要整份重建 |
| 并发安全 | 没有跨进程锁；不建议多个 `prepare` 同时写同一份数据目录 |
| Agent 自主规划 | 流程是固定 DAG，不引入不可预测的多步 agent |

这些「不做」不是缺陷清单，而是当前定位的取舍。第 04 篇会讨论哪些值得补、哪些不该补。

## 5. 技术栈与目录

### 5.1 技术栈

| 层 | 选择 |
| --- | --- |
| 语言 | Python 3.13 |
| 包管理 | uv |
| 配置 | TOML + pydantic v2 |
| 切块 | chonkie + tiktoken |
| 关键词检索 | bm25s |
| 向量 | numpy + langchain-openai `OpenAIEmbeddings` |
| 重排 | langchain-reranker |
| LLM | langchain `init_chat_model`（OpenAI 兼容端点） |
| 编排 | LangGraph |
| CLI | argparse |

### 5.2 目录地图

```text
src/fastrag/
├── __init__.py / api.py       # 公共 API
├── __main__.py                # python -m fastrag
├── domain.py                  # Chunk / ScoredChunk / SearchPlan / AnswerResult / AnswerEvent
├── errors.py                  # FastragError
├── version.py
├── config/
│   ├── models.py              # pydantic 配置 schema 与交叉校验
│   └── loader.py              # FASTRAG_HOME / TOML / .env / endpoint key
├── ingest/
│   ├── download.py            # 抓取 Markdown
│   ├── chunker.py             # 剥模板头、切块、写 chunks.jsonl
│   └── artifacts.py           # ArtifactKey / manifest / 原子写
├── index/
│   ├── store.py               # ChunkStore：唯一真源 + 全文件摘要
│   ├── dense.py               # 向量构建、增量复用、向量检索
│   └── bm25.py                # BM25 构建、校验、检索
├── retrieve/
│   ├── fusion.py              # RRF
│   └── rerank.py              # cross-encoder 重排适配
├── llm/
│   ├── client.py              # 模型构建、fallback、空回答检测
│   └── prompts.py             # 提示词加载与渲染
├── pipeline/
│   ├── resources.py           # 懒加载资源包
│   ├── nodes.py               # 图节点与降级逻辑
│   ├── graph.py                # StateGraph 装配
│   └── runner.py              # RagPipeline / ask / stream
├── cli/
│   ├── main.py                # 唯一 argparse 入口
│   ├── format.py              # 命中格式化
│   └── commands/              # 九个命令模块
└── resources/

    └── prompts/               # search_plan / answer / chat
```

依赖方向是单向的：

```text
cli → pipeline → index / retrieve / llm → ingest / config → domain / errors
```

新增代码时先问自己「它属于哪一层」，不要反向 import，也不要把 LangChain 的 `Document` 带进 `domain` 或 `pipeline`。

## 6. 五分钟跑起来

### 6.1 准备

```powershell
uv sync
Copy-Item .env.example .env
# 编辑 .env，填入 SILICONFLOW_API_KEY
uv run fastrag --help
```

Bash 下把 `Copy-Item` 换成 `cp`。

### 6.2 建库

```powershell
uv run fastrag download
uv run fastrag prepare
```

- `download`：抓取示例文档到 `data/langchain-docs/`；
- `prepare`：切块 → 嵌入 → 建 BM25，产物在 `data/` 下。

`prepare` 会调用嵌入接口，第一次跑通常需要几分钟并产生费用。语料没变时不要反复跑；如果只是想确认代码能跑，至少先看一眼 `data/` 里是否已有产物。

### 6.3 查一查

```powershell
uv run fastrag search "human in the loop" -k 5
uv run fastrag rrf "how does human in the loop work" -n 5
uv run fastrag rerank "human in the loop" -n 5
uv run fastrag ask
```

- `search`：只走 BM25，最快，不调用嵌入；
- `rrf`：BM25 + 向量，按名次融合，会调用嵌入接口；
- `rerank`：先 BM25 取候选，再走重排端点；
- `ask`：进入交互循环，输入问题后流式输出回答。

### 6.4 全本地模式

如果你在本机用 llama.cpp 起了嵌入与 LLM 服务：

```powershell
$env:NO_PROXY = "127.0.0.1,localhost"
uv run fastrag --config local prepare
uv run fastrag --config local ask
```

`local` profile 默认假设：

- 嵌入服务：`http://127.0.0.1:9931/v1`，模型 `bge-m3`，1024 维；
- LLM：`http://127.0.0.1:9938/v1`，模型 `qwen3-4b-instruct`；
- 向量目录：`data/embeddings-bge-m3`。

注意：默认配置仍走云端；`local` profile 只是把端点换成本机服务，`download` 和第一次建库仍然需要网络/本地服务可用。如果本地服务端口或模型名不同，复制一份 TOML 改掉即可，不必改代码。

## 7. 三种使用方式

### 7.1 CLI

适合建库、调试与手动问答。所有命令共享全局参数：

```powershell
uv run fastrag --config local search "..." -k 5
uv run fastrag -v rrf "..." -n 5
uv run fastrag --version
```

`--config`、`-v`、`--version` 可以放在子命令前，也可以放在后面；`main.py` 会先把它们抽出来再解析。

### 7.2 库：一次性问答

```python
from fastrag import ask

result = ask("What is human-in-the-loop?")
print(result.answer)

for hit in result.sources:
    chunk = hit.chunk
    print(hit.rank, hit.score, hit.channel, chunk.source, chunk.start, chunk.end)
```

`fastrag.ask()` 会自动 `load_env()` 并加载默认配置。返回的 `AnswerResult` 包含：

- `answer`：最终回答；
- `sources`：融合后的 `ScoredChunk` 元组；
- `plan`：本次的 `SearchPlan`；路由降级时为 `None`，此时 `metadata["queries"]` 是原问题；
- `metadata`：模型、provider、fusion、prompt 哈希、耗时、是否检索、两路查询等。

### 7.3 库：复用流水线

```python
from fastrag import RagPipeline, load_env

load_env()  # 如果使用云端 key，必须自己加载 .env
pipeline = RagPipeline.from_config()

result = pipeline.ask("What is human-in-the-loop?")

for event in pipeline.stream("What is RAG?"):
    if event.kind == "token":
        print(event.text, end="")
    elif event.kind == "done":
        print("\n", event.result.metadata)
```

注意：`RagPipeline.from_config()` **不会**读 `.env`；只有 CLI 和模块级 `ask()/stream()` 会。直接用 `RagPipeline` 时，要么先 `load_env()`，要么确保环境变量已经在进程里。

同一个 `RagPipeline` 会缓存资源，适合连续问多个问题；不同 `Config` 可以各建一个实例，互不干扰。

## 8. 配置总览

### 8.1 只有一份 TOML

默认配置在 `src/fastrag/resources/config/fastrag.toml`，本地 profile 在同目录的 `fastrag.local.toml`。所有字段都由 `config/models.py` 的 pydantic 模型校验，`extra="forbid"`，拼错键会直接报错。

主要节：

| 节 | 作用 |
| --- | --- |
| `[paths]` | 文档、chunks、向量、BM25 的目录 |
| `[endpoints.*]` | OpenAI 兼容端点与 key 环境变量 |
| `[chunking]` | chunk_size、overlap、模板头正则 |
| `[embedding]` | 嵌入端点、模型、维度、批大小、超时 |
| `[llm.route]` / `[llm.answer]` | 路由模型与回答模型，可各自 fallback |
| `[reranker]` | 重排端点、模型、超时 |
| `[bm25]` | method、stopwords、min_score |
| `[retrieval]` | 两路候选数、top_n、context_chunks |
| `[fusion]` | `rrf` 或 `rerank`、rrf_k、通道权重 |
| `[download]` | 索引 URL、base URL、并发、超时、重试、排除规则 |

### 8.2 解析顺序

显式传 `--config` 时（按顺序尝试）：

```text
--config <值>
  ├─ 该值作为路径存在？     → 用它（相对路径按 cwd 解析）
  ├─ 值 == "default"？     → $FASTRAG_HOME/config/fastrag.toml
  │                          否则包内 resources/config/fastrag.toml
  └─ 否则                  → 包内 resources/config/fastrag.<值>.toml
```

不传 `--config` 时：

```text
FASTRAG_CONFIG
  > $FASTRAG_HOME/config/fastrag.toml
  > 包内 resources/config/fastrag.toml
```

- `--config default` **不等于**「不传 `--config`」：它会跳过 `FASTRAG_CONFIG`，只走用户配置/包内模板这两级；如果当前目录有名为 `default` 的同名路径，还会先被当成路径；
- `--config local` 同样先找一个名为 `local` 的文件，找不到再找包内 `fastrag.local.toml`；
- `FASTRAG_HOME` 默认是源码树根（editable 安装）或当前目录（wheel 安装）；
- `[paths]` 里的相对路径、`.env` 都在 `FASTRAG_HOME` 下解析。

### 8.3 配置如何影响行为

几个最容易混淆的旋钮：

| 配置 | 影响 |
| --- | --- |
| `retrieval.top_n` | 融合后的排名截断，也是 CLI 的默认输出条数 |
| `retrieval.context_chunks` | 进入回答提示词的片段数上限；为空时用 `top_n`，实际条数是 `min(context_chunks, top_n)`，因为 `fuse` 已先截到 `top_n` |
| `retrieval.bm25_candidates` / `vector_candidates` | 每路先召回多少条再融合 |
| `fusion.method` | `rrf` 不初始化重排器；`rerank` 会初始化并可能降级 |
| `fusion.weights` | 只对 RRF 生效，键必须包含 `bm25` 与 `vector` |
| `llm.*.thinking` | `false` 时通过 `extra_body.setdefault` 注入 `enable_thinking=false`；`true` 时不主动注入。两种情况都以 `extra_body` 里显式设置的 `enable_thinking` 为准 |
| `api_key_env = ""` | 视为本地服务，占位 key 为 `local`，不读环境变量 |

## 9. 数据产物

`prepare` 之后，`data/` 下最主要的三类产物：

### 9.1 `chunks.jsonl`

唯一真源，每行一个 chunk：

```json
{"id":"a1b2c3d4e5f60718","source":"data/langchain-docs/...md","start":123,"end":456,"token_count":210,"text":"..."}
```

关键不变量：

- `id = sha1(source + "\0" + text)[:16]`；
- `source` 通常是相对 `FASTRAG_HOME` 的路径；文件在 home 之外时会退回绝对路径；
- `text` 必须等于原文件 `[start:end]`（模板头剥离后的偏移已经加回）；
- 同一个 chunk 内容不变，id 就不变。

### 9.2 `vectors.npy` + `manifest.json`

- `vectors.npy`：L2 归一化的 float32 矩阵，行顺序与 manifest 的 `ids` 一致；
- `manifest.json`：来源摘要、模型、维度、归一化标记、条数、ids。

向量复用的判断是「模型/维度/形状一致 + ids 能对上」，**不比较 chunks 文件摘要**。这是有意的：chunk id 内容寻址，在目标规模下可以把 id 相同视为文本相同（id 是 64 位截断哈希，碰撞概率可忽略）。语料变化时，仍留在新语料中的旧 id 会复用旧行，新 id 只补嵌缺少的部分；被删除的 chunk 不会保留。

### 9.3 `bm25-index/` + `meta.json`

BM25 只保存 chunk id 和索引文件，检索命中后再回 `ChunkStore` 取正文。加载前会校验：

- `meta.json` 存在；
- `kind` 是 `bm25`；
- `source_digest` 与当前 `chunks.jsonl` 一致；
- `method` / `stopwords` 与当前配置一致。

任何一项不匹配都会提示重新 `fastrag index` 或 `fastrag prepare`。

### 9.4 增量行为

| 变化 | chunks | 向量 | BM25 |
| --- | --- | --- | --- |
| 文档内容变化 | 重新切，生成新 id | 旧 id 复用，新 id 补嵌 | 必须重建 |
| 切块参数变化 | 全部重新切 | 大部分 id 变化，按 id 复用剩余 | 必须重建 |
| 嵌入模型/维度变化 | 不变 | 全量重嵌 | 不受影响 |
| `bm25.method` / `stopwords` 变化 | 不变 | 不受影响 | 必须重建 |
| `bm25.min_score` 变化 | 不变 | 不受影响 | 不需要重建，查询期立即生效 |
| 仅移动/重命名源文件 | id 变化（source 参与哈希） | 对应块重嵌 | 必须重建 |

`prepare` 每次都会重写 `chunks.jsonl` 并重建 BM25；向量的「增量」只发生在 `ensure_vectors` 内部。这是当前实现的取舍：切块和 BM25 足够快，向量才值得省。

## 10. 适合谁

**适合：**

- 想完整读一遍小型 RAG 实现的人；
- 有一个几千到几万 chunk 的 Markdown 语料、想本地跑通混合检索的人；
- 想用 OpenAI 兼容端点快速替换模型/嵌入/重排的人；
- 想把 FastRag 当骨架，改造成自己业务流程的人。

**不太适合：**

- 需要开箱即用的 Web 产品或多租户服务；
- 语料是 PDF/HTML/扫描件；
- chunk 数到百万级、需要 ANN 或分布式检索；
- 需要严格引用核验、审计、权限与可观测性；
- 完全不想碰 Python 和配置文件的人。
