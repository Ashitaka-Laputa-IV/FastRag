# 全本地链路首 token 基准

- 日期：2026-10-26
- 分支：`bench`
- 配置：`config/fastrag.local.toml`
- 数据：`data/bench/results-2026-10-26-all-local.json`（`created_at = 2026-10-26T10:22:51Z`）
- 日志：`data/bench/bench-run-20261026-all-local.log`
- 目的：整条 RAG 链路都跑在本机，测「端到端 -> 首 token」的耗时，和云端配置做对照。

## 0. 摘要

- 全本地跑完 9 次，端到端（到首 token）中位数 **2508 ms**，比云端默认配置的 **7496 ms** 快约 **3 倍**。
- 耗时构成：检索规划 **1084 ms（43%）**、首 token **1454 ms（58%）**、召回 42 ms、融合 0.0 ms。
- 规划从云端的 6937 ms 降到 1084 ms，是端到端变快的主要原因；代价是生成首 token 从 491 ms 变慢到 1454 ms（本地 4B 处理长上下文更慢）。
- 召回用本地 `bge-m3`（1024 维），中位数 **41.5 ms**，比云端 2560 维嵌入的 142 ms 快约 3.4 倍，且不再依赖公网。
- 9 次运行全部正确触发检索（`need_search = true`），没有出现误判。

## 3. 与云端配置对比

云端数据来自 [`bench-first-token.md`](bench-first-token.md)（同一天、同 3 个问题、同样首 token 口径、`[llm.*].thinking = false`），差异是模型与嵌入都在 SiliconFlow，且走公网。

| 阶段 | 云端中位数 (ms) | 全本地中位数 (ms) | 变化 |
| --- | ---: | ---: | --- |
| 检索规划 | 6936.6 | 1083.6 | **-84%** |
| 召回 | 141.6 | 41.5 | -71% |
| 融合 | 0.1 | 0.1 | 0.0% |
| 首 token | 491.0 | 1453.9 | **+196%** |
| **端到端** | **7496.4** | **2508.4** | **-67%** |

- 变快的部分：规划与召回；变慢的部分：生成首 token。总体净收益约 5 s。
- 全本地不再受公网波动影响：云端同配置的 9 次运行极差 6.5–14.5 s，全本地只有 2.34–2.91 s。
- 首 token 变慢的主要原因是本地 4B 要处理约 3–4k token 的检索上下文；直接测短提示词时它只要 30 ms（见 [`llm-ttft.md`](llm-ttft.md)），长上下文预填充才是瓶颈。
- 规划只占 1.08 s，进一步压缩的空间有限；如果要继续降端到端，优先优化生成侧（更小的上下文、更强的本机模型或量化）。

## 4. 复现

```bash
# 前置：本地已启动 bge-m3（9931）与 qwen3-4b-instruct（9938）
esl start bge-m3
esl start qwen3-4b-instruct

# 第一次会嵌入 2625 个 chunk（约 2.5 分钟），之后复用 data/embeddings-bge-m3/
env -u ALL_PROXY -u all_proxy -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
  uv run python -m fastrag.bench --config config/fastrag.local.toml --runs 3
```

- 只想生成向量：把 `fastrag.embed_chunks` 的配置指到 `config/fastrag.local.toml`，或直接调用 `ensure_vectors`。
- 切回云端：不加 `--config` 即使用 `config/fastrag.toml`。

## 5. 局限

- 只测首 token，回答质量与完整生成耗时未评估；4B 模型在事实性、完整度上大概率弱于云端模型。
- `bge-m3`（1024 维）与云端 `Qwen3-Embedding-4B`（2560 维）的检索质量没有做量化对比，只抽查了 Q1 的 top 5 是否相关。
- 每题 3 次样本，但全本地方差小，中位数已经足够稳定。
- 本机同时跑嵌入与对话两个 llama.cpp 服务，显存/内存竞争可能影响绝对数值；换机器或换量化会不同。
- 本地模型未做并发测试，多用户场景下的排队未评估。
